# Notebook 1.6.3 — continuous eraser correctness and latency

Started from clean synchronized dev at v1.6.2 (`512d7fc`). Existing tests had
covered isolated cuts but did not reproduce sustained dense-marker rubbing.

## Reproduced failures

- Outlier recovery cleared the local previous point but retained the previous
  queued path endpoint, producing a straight erasure through the gap.
- Leaving the drawable area or entering a modal widget did not end normal
  erasing, so reentry could connect two distinct contacts.
- Accepted eraser samples did not update their kernel timestamp. Duplicate
  stationary samples could repeatedly enter the geometry path.
- Zoom throttled refresh only, not geometry; 121 queued samples resulted in
  121 full document eraser passes.
- Wide square nib footprints were clipped as overlapping full surfaces for
  every recorded center point. A 600-point continuous-cut regression reached
  479,233 vertices; the new representation stays below 60,000 for that fixture.

## Corrections

Normal and zoom erasing share the path accumulator and geometry cadence.
Recovery flushes the preceding path before starting a new contact island;
release, canvas exit and modal interception clear continuity state. Timing uses
accepted kernel samples and scales the outlier distance to screen units at 2x.
Duplicate positions are ignored; exact collinear continuations are compacted,
while turns and reversals remain intact. Release flushes the final geometry and
cancels any redundant queued callback. Finger erasing also blocks idle cleanup
and autosave while active.

For a raw marker segment, the immediately preceding footprint already owns the
shared nib. Subtracting that footprint before clipping removes duplicated
surfaces. Set-union coverage outside the eraser remains the same. Surviving
centerline runs retain their brush metadata. Storage format, cloning, export
and undo interfaces remain unchanged.

## Validation

`make ci`: zero lint warnings; all 47 configured Lua suites; complete unchanged
translations; 16 Python benchmark tests; package integrity/contents.
New failing-before regressions cover outlier bridges, canvas reentry, sample
clock, stationary contacts, zoom coalescing, preserved turns, single-sweep undo,
redo, timer cleanup and sustained marker geometry growth. Pressure changes,
curved/reversing markers and distances to independent polyline oracles preserve
ink away from the nib and remove ink inside it. Tests include authoritative
cache repair after zoom erasing and panning.

Native `tools/bench-eraser-live.lua` runs 121 samples at 8 ms intervals over a
1001-point curved marker, including production canvas repaint. Same runtime,
600×800 BB8, JIT on, separate sequential baseline/current processes:

| Zoom | Marker width | Model calls old/new | CPU total old/new (ms) | Peak model call old/new (ms) | Vertices old/new |
|---|---:|---:|---:|---:|---:|
| 1x | 48 | 16 / 16 | 7813 / 481 | 709 / 39 | 1,033,804 / 67,079 |
| 1x | 120 | 16 / 16 | 27148 / 746 | 2414 / 89 | 3,566,633 / 118,684 |
| 2x | 48 | 121 / 16 | 10292 / 484 | 116 / 37 | 1,033,804 / 67,079 |
| 2x | 120 | 121 / 16 | 41805 / 784 | 485 / 92 | 3,566,633 / 118,684 |

Each final native framebuffer equals authoritative fresh vector rendering.
Before/after PNG comparison: width-48 fixtures have identical pixels; width-120
fixtures remove 19 pixels at 1x and 39 at 2x that the old code left behind.
An independent distance check puts every changed pixel strictly inside the
circular nib (maximum page-space distances 7.313 and 7.711, radius 8). No
outside-path pixels change. These remnants appeared as a horizontal ink seam
inside the erased region in the old implementation.

The standard 12-isolated-cut bench was also run with JIT on and off. New/old CPU
ratios are approximately 0.91 (width 48), 0.40–0.43 (width 120), and 0.08–0.09
(width 300). Result geometry counters differ intentionally; pixel/oracle tests,
rather than identical vertex counts, establish correctness.

Raw data: `results/2026-10-02-eraser-live-{before,after}-desktop.txt` and
`results/2026-10-02-eraser-geometry-desktop.json`.

## Limits

These are native offscreen CPU measurements, not end-to-end physical e-ink
latency. The configured Kindle was unreachable over SSH, so no new physical
device claim is made. No screen waveform or cadence default was changed.
Existing notebooks are not rewritten; previously accumulated filled geometry
is preserved, rather than being approximated or silently discarded.
